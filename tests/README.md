# Запуск тестов

Общий runner — pytest. Старые `macos/run*.py` запускаются отдельными процессами,
последовательно, с таймаутом и отдельным логом. Переписывать их на pytest не нужно.

Установка из корня репозитория в выбранное Python 3.11+ окружение:

```sh
python -m pip install -e '.[dev]'
python -m pytest
```

Обычный запуск выполняет переносимые Python-тесты на Windows/Linux/macOS.
В том числе запускается `macos/run_initaddr.py`: несмотря на расположение,
он проверяет только Python-препроцессор и не компилирует библиотеки.
Нативные и симуляторные проверки выводятся как SKIPPED с причиной.

```sh
# Все автоматические macOS-проверки вместе с Python-тестами
python -m pytest --run-native

# Только нативные; один сценарий можно выбрать через -k
python -m pytest --run-native -m native
python -m pytest --run-native -k run_hookaddr

# Симуляторный сценарий: указать уже загруженный iOS Simulator
python -m pytest --run-simulator --simulator-udid YOUR_UDID -m simulator

# Вся пачка, включая симулятор
python -m pytest --run-native --run-simulator --simulator-udid YOUR_UDID

# Список сценариев, отчёт для CI и настройка таймаута
python -m pytest --collect-only -q
python -m pytest --run-native --junitxml=build/test-results.xml --harness-timeout 900
```

Требования и ограничения:

- Нативные тесты требуют macOS на Apple Silicon и arm64 Python, Apple toolchain,
  а для большинства сценариев — MachOMerger. При явном запуске отсутствие
  обязательного инструмента считается ошибкой. На другой ОС/архитектуре — SKIP.
- Runner выбирает мерджер через общий поиск ColdHook (env, текущий каталог,
  PATH). Прямой запуск скриптов использует тот же поиск и требует установленный
  Python-пакет ColdHook. Каталоги сборки не проверяются автоматически.
- Logos-сценарии могут пропускаться без Theos. Их сообщения `SKIP` учитываются
  как пропуск, а не успешный тест.
- `run_swiftui_shared.py` запускается с `--test`: build-for-testing, сборка
  runtime и Swift/C-хуков для macOS, shared-патч приложения и фреймворка, подпись
  и XCTest UI-запуск. Проверяются подмена текста с вызовом original, значение
  frameworkProbe() == 777 и нажатие кнопки, которое после патча возвращает строку
  вместо краша. Нужна активная графическая macOS-сессия и разрешения XCTest
  на управление UI. Результат сохраняется в SharedHooks.xcresult во временном
  каталоге сборки. `--no-run` остаётся ручным режимом сборки, не частью тестов.
- Симулятор запускается только по явному флагу и UDID: сценарий устанавливает
  тестовое приложение и выполняет существующий simulator harness. Нужны полный
  Xcode, iOS Simulator SDK/runtime и уже загруженное устройство. Runner не
  выбирает и не загружает устройство автоматически.
- На Windows эти C/ObjC/Swift-сценарии не становятся переносимыми от использования
  pytest: нужна отдельная macOS CI-задача. Windows проверяет Python-логику.
- Общие build-каталоги пока сохранены. Не запускай две нативные пачки одновременно;
  запуск через pytest-xdist (`-n`) с нативными флагами запрещён.
- Таймаут по умолчанию — 600 секунд на скрипт. На macOS при таймауте убивается
  группа дочерних процессов. На Windows переносимый скрипт завершается отдельно.
- При ошибке отчёт содержит команду, путь к полному логу и последние 16000 символов.
  Полный вывод также прикрепляется к pytest report; логи находятся в его временном
  каталоге (путь напечатан при сбое). `--basetemp` позволяет выбрать этот каталог,
  но pytest очищает его перед запуском — используй только отдельный тестовый путь.

Падение сценария не останавливает остальные тесты. Используй `-x`, если нужно
остановиться на первой ошибке. Итоговая сводка различает passed/failed/skipped.
